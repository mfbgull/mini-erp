# Plan: Return as Payment — Two Separate Ledger Entries

## Problem
When a return is processed with "adjust" disposition (credit applied to another invoice), the current approach:
- Creates a RETURN entry grouped under the source invoice
- Creates a zero-amount PAY019 payment (no ledger entry)
- The visual grouping is confusing and doesn't clearly show the credit flow

## Solution
Create two separate entries:
1. **RETURN entry** (credit) — audit trail for the return, shown as standalone/ungrouped
2. **PAYMENT entry** (credit) — linked to the target invoice via `payment_allocations`, reduces its balance

---

## Changes

### Step 1: Server — Create PAYMENT entry instead of zero-amount adjustment

**File:** `server/src/controllers/invoiceController.ts` — adjust disposition block (lines 1128-1217)

Current code creates a zero-amount payment with `amount: 0`. Change to:
1. Create a real payment with `amount = allocAmount` (positive, representing the credit)
2. Allocate it to the target invoice
3. Create a PAYMENT ledger entry (credit) linked to this payment

```typescript
// Before (current):
const adjustPaymentId = InvoiceModel.createPayment(
  db, adjustPaymentNo, invoice.customer_id, todayDate,
  0,  // no actual cash movement
  'Credit', null,
  `Credit adjustment from return on ${invoice.invoice_no}`
);

// After:
const adjustPaymentId = InvoiceModel.createPayment(
  db, adjustPaymentNo, invoice.customer_id, todayDate,
  allocAmount,  // actual credit amount
  'Credit', null,
  `Return credit applied to ${targetInvoice.invoice_no}`
);

// Allocate the credit to the target invoice
InvoiceModel.createPaymentAllocation(db, adjustPaymentId, targetInvoiceId, allocAmount);

// Create PAYMENT ledger entry (credit to reduce AR on target invoice)
createLedgerEntry(
  invoice.customer_id,
  'PAYMENT',
  adjustPaymentNo,
  0,
  allocAmount,
  `Return credit from ${invoice.invoice_no} applied to ${targetInvoice.invoice_no}`
);
```

### Step 2: Client — Grouping logic handles RETURN as standalone

**File:** `client/src/utils/ledgerGrouping.ts`

The `extractInvoiceNo` function currently links RETURN entries to the target invoice via `linked_invoice_no`. Change to make RETURN entries standalone (ungrouped):

```typescript
function extractInvoiceNo(entry: LedgerEntry): string | null {
  // RETURN entries are standalone — don't group under any invoice
  if (entry.transaction_type === 'RETURN') {
    return null;
  }
  if (entry.linked_invoice_no) {
    return entry.linked_invoice_no;
  }
  if (entry.transaction_type === 'INVOICE' || entry.transaction_type === 'CANCELLATION') {
    return entry.reference_no;
  }
  const match = entry.description?.match(/(?:for|against|on)\s+(INV-[\w-]+)/i);
  return match ? match[1] : null;
}
```

Also update the balance calculation to only count PAYMENT entries (remove the RETURN/ADJUSTMENT case):

```typescript
if (group) {
  group.children.push(entry);
  if (entry.transaction_type === 'PAYMENT') {
    group.totalPaid += entry.credit || 0;
  }
  group.balance = group.invoice.debit - group.totalPaid;
}
```

### Step 3: Server — Clean up old data (one-time)

**New file:** `server/scripts/fix_return_entries.js`

Migrate existing data: for any RETURN entry that has a `linked_invoice_no` pointing to a different invoice, create the corresponding PAYMENT entry and allocation. Then rebuild ledger balances.
